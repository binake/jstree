- 所有 API 响应均统一使用 `jsonify` 返回 JSON 格式，错误场景通过设置 HTTP 状态码（如 400, 403, 404）并携带 `{'error': '...'}` 字典进行标识。
- 在执行写操作（增删改）前，普遍采用 `get_or_404` 或 `first_or_404` 确保目标资源存在，并在事务结束后显式调用 `db.session.commit()`，异常时执行 `rollback()`。
- 权限校验逻辑高度一致：非管理员用户在进行敏感操作（如激活节点、查看进度）时，均通过比对 `user.module` 与目标资源 `module` 的集合交集来决定是否放行。
- 节点状态计算采用动态注入模式：在 `build_jsmind_data` 中根据当前树的 `mode`（tree/path）递归计算每个节点的 `status`（locked/unlocked/activated），而非仅依赖数据库静态字段。
